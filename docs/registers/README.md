## Notes / caveats

- **Overlapping field bits are real.** Some registers list fields whose bit ranges overlap
  (e.g. a composite `BIT_POS [4:0]` alongside individual `MSG_START [0]` / `MSG_DONE [1]`).
  These are genuine Broadcom alias / multi-view field definitions taken verbatim from the SDK
  `*_GET` macros — not a parsing artifact. The same physical register bits are decoded
  differently depending on the operation.
- **Descriptions are register-granularity.** The English prose describes the register; individual
  field bits carry names but usually no prose (this is all Broadcom ships).
- **17 registers (1%) lack a description** — these are mostly debug/reserved registers with no
  text in the SDK source.
- Field bit ranges are derived from the SDK accessor macros; very wide fields that span 32-bit
  words are decoded per-word.
