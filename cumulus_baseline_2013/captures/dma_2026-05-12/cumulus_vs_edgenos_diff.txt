ROOT CAUSE (4 fixes for EdgeNOS):

1. CMIC_ENDIAN_SEL must be 0x05050505, NOT 0x04000004/0x04040404.
   Each byte has bit 0 = byte-swap-enable for one of four endian
   domains (PIO, DMA_PACKET, DMA_OTHER, MSI). All four must be set
   on a big-endian PPC host. With only bit 2 set (our value), the
   chip reads DCB bytes in reversed order, finds no valid descriptor,
   and hangs the DMA channel.

2. PCIE_EP_AXI_CONFIG (0x2104) MUST NOT be zeroed. Cumulus has 0x58
   there. Our bde_open() was explicitly zeroing it via PCI config
   write — that broke the outbound AXI bridge.

3. OARR_1, OARR_2 must remain 0 (disabled). Only OARR_0 (with its
   firmware default of 0xf8 / upper 0x80) is in use on Cumulus.
   Our previous session enabled OARR_1/2 hoping it would help —
   it didn't, and is the wrong thing to do.

4. PAXB_ENDIAN (0x2030) should be 0xf3, not 0xf2 (bit 0 swap-enable
   for PAXB outbound).

Fixed in EdgeNOS commit 7fbfb7d's bde_interface.c successor (this
session): bde_set_dma_endianness() now writes 0x05050505 to
CMIC_ENDIAN_SEL and 0xf3 to PAXB_ENDIAN; bde_open() no longer
touches PCIE_EP_AXI_CONFIG or OARR_*.
